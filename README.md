# NODIA 要件定義書

## 1. ペルソナ

### 想定ユーザー

* 学生
  * 勉強・課題・予定・活動などの情報を整理・接続し、学習にも活用できるようにする。
  * 例：数学のノードに課題・授業予定・学習記録などをまとめて管理する。

## 2. ノードの機能について

### NODIAでは、ノードに機能を持たせることができる。

* 数学 → 科学計算電卓
* 英語 → 単語学習機能
* 課題 → ToDo・期限管理
* 予定 → カレンダー
* 学習 → 学習記録

## 3. 進行

### 現在決まっていること

* 学生向けのアプリとして開発する
* まずは学業に絞る
* 教科に応じた機能をノードにつける
* ノード同士を接続できるようにする
* ノードには機能を持たせる
* 初期段階ではノードごとの機能を固定する

### 将来的な構想

* ノード同士の関係にも意味を持たせられるようにする
  * 例：`{ノード} --理由→ {ノード}`

## 4. データ構造とキャンバス

### 大元のノードツリー

NODIAでは、ユーザーが持つ情報を大元のノードツリーとして管理する。

例：

ユーザー
* 金沢大学
* 起業
* 勉強
* 創作活動


この大元のノードツリーを、情報の保管・管理の基盤とする。

各ノードは、必要に応じて他のノードや機能から参照できる。

### キャンバス

キャンバスは、ユーザーが情報を自由に整理・表現するための空間とする。

イメージとしては、

> **テーブルの上にノードを置き、その上にルーズリーフを広げて作業する。**

キャンバス上では、以下のような要素を扱えるようにする。

* ノード
* 付箋
* Markdown
* 画像
* 手書き・描画
* ノードツリーの一部分の表示

キャンバス上に表示されるノードやノードツリーは、大元のデータを参照して表示する。

そのため、キャンバス上の表示と大元のデータを別々に管理するのではなく、**大元のデータを必要な場所で表示・利用する**構造を目指す。

### NODIAにおける役割

```text
大元のノードツリー
    ↓
情報を保持する

キャンバス
    ↓
情報を自由に整理・表現する

ノード
    ↓
情報への入口・機能を持つ

接続
    ↓
情報同士の関係を表現する
```
